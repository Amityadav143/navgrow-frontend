🏗️ System Architecture

Three-Tier Architecture

Navgrow uses a modern, scalable three-tier architecture:

Layer Components Technology
Frontend React SPA, Components, Context API, localStorage React 18, Vite, TailwindCSS, Framer Motion
API Gateway JWT Auth, CORS, Request/Response Interceptors, Rate Limiting Axios + Interceptors
Backend REST APIs, Business Logic, Authentication, Payment Processing Spring Boot or Node.js, PostgreSQL, Redis
Data Layer Relational Database, Cache Store, File Storage PostgreSQL, Redis, AWS S3

Component Architecture

The frontend is organized into logical component groups:

  • src/components/ - Reusable UI components (40+ files, 280KB)
  • src/pages/ - Full-page components (20+ files, 408KB)
  • src/context/ - State management (AuthContext, CartContext)
  • src/hooks/ - Custom hooks (useApi, useSeo)
  • src/lib/ - API client, utilities, constants

🗄️ Database Schema

Navgrow uses PostgreSQL with normalized relational design:

Core Tables

  • users - User profiles, authentication data
  • products - Product catalog, pricing, stock
  • orders - Order records, payment status
  • order_items - Individual items in orders
  • quotes - Quote requests from customers
  • coupons - Discount codes
  • contacts - Contact form submissions
  • articles - Blog/news content
  • reviews - Product reviews

Key Relationships

Relationship Type Reason
User → Orders 1:N One user can place multiple orders
Order → OrderItems 1:N One order contains multiple items
Product → OrderItems 1:N One product appears in multiple orders
Product → Reviews 1:N One product has multiple reviews

🔌 API Architecture

REST API Endpoints

Category Endpoint Method Purpose
Auth /auth/register POST User registration
/auth/login POST User login
/auth/refresh POST Refresh JWT token
/auth/forgot-password POST Password reset request
Products /products GET List products (paginated, filtered)
/products/:slug GET Get product details
/products/:id/reviews GET/POST Get/add product reviews
Orders /orders POST Create new order
/orders/mine GET Get user's orders
/orders/:id/status PATCH Update order status (Admin)
/orders/payment/verify POST Verify Razorpay payment
Admin /admin/analytics/dashboard GET Dashboard metrics

Request/Response Example

Example: Create Order

POST /orders
{ "customerName": "Rajesh Kumar", "customerEmail": "rajesh@company.com", "items": [ {"productId": "prod-123", "quantity": 2} ] }

Docker Deployment

Frontend containerized with multi-stage build:

  • Build stage: Node.js 18 alpine, npm install, npm run build
  • Production stage: Serve dist folder on port 3000
  • Size: ~100MB final image

Scalability Architecture

Frontend: Vercel or Netlify (auto-scaling)
Backend API: Kubernetes pods with auto-scaling (>1000 req/sec)
Database: PostgreSQL RDS with read replicas
Cache: Redis for session & cart data
CDN: Cloudflare for static assets (images, CSS, JS)

🔐 Security & Compliance

Authentication

  • JWT Tokens: 1-hour access token, 30-day refresh token
  • Password Hashing: Bcrypt with 12 rounds
